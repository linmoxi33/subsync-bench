# 实测记录：ffsubsync 0.5.1 到底哪里不可靠

本文记录做这个工作台之前对上游做的全部实测。每条都可以用
`fixtures/build_media.py` 生成的素材复现，对应的断言在 `tests/` 里。

素材：110 秒真实合成语音（edge-tts），14 个语音窗口，间隔刻意不均匀——
这样"能对齐"必须依赖语音的**节奏模式**，而不是"有没有声音"。

---

## 1. 静音参考：返回 0，写出坏文件

```
ffsubsync silent.mp4 -i shifted.srt -o out.srt
→ retval 0
→ INFO score: 1756.400
→ INFO offset seconds: 0.140
→ INFO framerate scale factor: 1.042
→ 写出 out.srt
```

`out.srt` 是合法 SRT，内容是**未被平移的原始字幕**。文件本身完全正常，
唯一的问题是它根本没对齐。

同一素材，正确对齐的 `score` 是 5285，错误影片是 1722–2675。
1756 落在错误区间里，但和 5285 同量级 ⇒ **这个数字无法设阈值**。

## 2. `--min-score` 与 `--skip-sync-on-low-quality` 都不生效

```
silent.mp4  + --min-score 1000000   → retval 0, score 1756, 仍然写文件
silent.mp4  + --skip-sync-on-low-quality → retval 0, 仍然写文件
```

原因：`--min-score` 默认值就是 `0.0`（`constants.DEFAULT_MIN_SCORE`），
而 `assess_alignment_quality()` 只在 `skip_sync_on_low_quality` 为真时才被调用。
也就是说，质量门禁存在，但默认永不触发；想触发就得手工填一个
**在未归一化分数上**的阈值——而上面已经证明那个分数不可阈值化。

## 3. 帧率猜测会静默吞掉字幕

第一版素材用的是调制粉噪（pink noise）当"语音替身"。结果：

```
输入 14 条 → 输出 4 条 → retval 0
日志：Skipped subtitle at index 6: Start time < 0 seconds（INFO 级）
```

两层原因，都值得记：

**(a) 粉噪骗不过 webrtcvad。** 上游 VAD 是在真实语音上训练的，在粉噪里只找到
5 个零散片段，于是对齐本身就错了。⇒ 测试素材必须是真实语音，否则测的不是同步工具。

**(b) 帧率猜错会把时间码推成负数，pysubs2 直接丢弃。** 上游会尝试
23.976/25 = 0.959 这类候选比例；当素材根本不需要缩放时，缩放后部分时间码变负，
写入器跳过它们，**INFO 级日志，retval 仍为 0**。

这是本项目存在的第二个理由：丢台词永远不可接受，而它默认是静默的。

## 4. `ffprobe` 缺失只影响内嵌字幕轨

```
WARNING ffprobe unavailable while enumerating subtitles: [WinError 2]
INFO    Video file appears to lack subtitle stream
```

不影响音频对齐路径。所以工作台把 `ffprobe` 标为**可选**，`ffmpeg` 标为必需。

## 5. 编码：GBK 字幕被当成 UTF-16

上游用 `chardet`/`charset_normalizer` 探测。自己写探测时踩到的坑值得记：

**任何偶数长度的字节串都能"成功"按 UTF-16 解码**，不抛异常。一条 7 字中文
GBK 字幕被解成 `탖쓎훗믄퓊`（韩文乱码），全程无报错。

修法：只在有 BOM 时才走 UTF-16，探测链里不再投机尝试。

## 6. 已对齐的字幕，上游会说"offset 0.08s"

```
truth.srt（精确对齐）→ offset seconds: 0.080, framerate scale 1.001
```

这不是 bug，是 30ms 帧粒度 + 相关性峰的自然抖动。但它意味着
**不能用"偏移是否为 0"判断是否需要对齐**，也不能拿 0.08s 去卡阈值。

---

## 由这些实测推出的设计决定

| 实测结论 | 工作台的做法 |
|---|---|
| `retval` 不可信 | 每次运行后重新解析并校验输出，不信任返回码 |
| `score` 不可阈值化 | 自算归一化余弦相似度（0–1），实测分离度 0.685+ vs 0.407− |
| 静音会静默产出坏文件 | 自己解码音频、算包络，静音在跑引擎前就拒绝 |
| 帧率猜测会吞字幕 | 比对条数，丢条则降级重试；仍丢则阻断导出 |
| 上游输出直接写目标路径 | 一律写项目内 staging，校验后才提升 |
| 局部错位无人报告 | 逐条算 onset 距离 + 语音覆盖率，点名具体条号 |
| 无状态 | 每次尝试落成 revision + receipt，输入哈希、参数、测量全记 |

---

## 被否掉的做法（避免重复踩）

**用局部互相关算逐条残差。** 对每条字幕取 ±2.5s 窗口，把该条的位置当模板做相关，
再和全局偏移比。在**完美对齐**的素材上实测：残差中位数 −0.315s，标准差 0.384s，
14 条里 9 条被误判为可疑。

原因：一个窄脉冲在 2.5s 窗口里的相关峰很宽，估计值主要反映窗口边缘效应，
而不是真实错位。换成 onset 距离 + 覆盖率后，完美对齐 0/14、注入 3 处错位命中 3/14。

**用"置信度增益"做门禁。** `confidence - null_confidence < 0.05` 就拦。
对已对齐的字幕，增益**合法地**就是 0 ⇒ 这条规则会否掉所有正确的空操作。
改成"对齐后仍需移动多少"（残差偏移），并用量测校准容差。

**用 `--force` 兼做跳过复检。** 用户会习惯性加 `--force`，
一旦它同时关掉复检，把视频换成静音的也能导出。现在三个开关各自独立：
`--force`（覆盖/接受过期）、`--allow-override`（接受被拒版本）、
`--skip-recheck`（跳过复检，唯一能关掉它的开关）。
